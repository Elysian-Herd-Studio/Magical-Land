# 鬃毛与尾巴全区域遮罩分色

2026-09-08：01 前发、后发、尾巴各加入 6 区，共 18 个独立色槽。

2026-09-09：扩展到前发 01–08、后发 01–06/08、尾巴 01–07，共 22 个部件款式，每部件 6 区。后发 07 和尾巴 08 留空。

## 开发者速览

`mane.png` 保存灰度纹理和手绘明暗，`mane_dyes/surfaces.json` 保存各模型面的分色边界。渲染时沿边界划分原有表面，用玩家选择的色阶映射灰度，保留原来的发丝纹理。

全部款式共用一张 256×256 图集，UV 按部件和方块集中排列。现有 22 个部件、297 个方块的 1782 个面均使用表面分区，每部件保留六个色区。01 前发按刘海宽度等分，后发按三层分支各分两色；03 尾巴保留整块分色，08 前发按六组毛束分色。资源对应关系见[鬃毛纹理与 UV](mane-shared-texture-repair.md)。

| 文件/模块 | 职责 |
| --- | --- |
| `mane_dyes/surfaces.json` | 按骨骼、方块和面保存分色多边形，1–6 为色区编号 |
| `ManeSurfaceMasks` | 校验表面分区，转换为随原骨骼运动的渲染顶点 |
| `mane_dyes/stripe01.json`、`style02.json` … `style08.json` | 兼容资源包使用的像素遮罩 |
| `ManeDyeMask` | 读取像素遮罩；模型与表面分区不匹配时沿用该路径 |
| `ModelConfig` | 保存每部件的 6 色；null 表示锁定跟随该部件主色，并迁移旧配置 |
| `ManeDye` + `ManePalette` / `BodyColorRamp` | 解析主色联动和色区锁，为独立颜色计算阴影/高光，保持原 alpha |
| `ManeTintTextures` | 按色阶生成动态图集，相同色阶共用一格；资源重载或退出时回收 |
| `ManePage` / `PonyRenderer` | 折叠式颜色控件；选择部件纹理并跳过旧挑染覆盖骨骼 |

例如后发 4 区设粉色、5 区设紫色，其余色槽为 null：4、5 区使用独立色阶，其余继承后发主色及其明暗。

维护时主要注意：

- 色区形状由遮罩决定，质感由基础贴图决定；用灰度反推色区会把阴影误当挑染。
- 改 UV 后同步对应遮罩。新增发型需同时更新遮罩、注册表和 `ManeDye` 支持范围。
- 各模型面拥有独立分区，可以共用基础贴图与 UV，同时使用不同颜色。原灰度像素继续决定明暗与纹理密度。
- 锁定色区继承完整色阶，确保手动阴影和高光也与主色连续。
- `Resources` 源贴图/模型与 `src/main/resources` 运行时版本一起维护。Blockbench 保存灰度源图，玩家配色由运行时生成。

独立检查工具在本地维护。

## 使用

在捏脸的“鬃毛”分类中选择前发、后发或尾巴，开启“遮罩分区调色”，再展开主色下的对应分色项。各款式使用自己的六区遮罩，三处部件可独立混搭。

- 每区锁定时跟随本部件主色和完整高光/阴影；解锁保留当时颜色，然后可以独立调整。
- 相邻的 4、5 区可设置为粉、紫，其余区跟随主色，即可手动搭配双带挑染。全部区域解锁后可做多色搭配。
- 每个部件独立保存 6 色，色区锁跟随本部件主色。前后发和尾巴的主色仍可联动。
- 更换款式沿用当前部件的 6 色，色区位置由新款式决定。不同配色组合可保存为角色预设。
- “全部色区跟随本部件主色”将当前部件的 6 色重新锁定；关闭总开关只停用分色，不清空配色。
- 异色色区自动计算明暗；与主色相同的色区复用主色完整色阶。逐色区手动阴影/高光编辑暂不提供。

分区调色默认关闭。迁移旧挑染配置时，前发/尾巴的旧色写入 4、5 区；后发 4 区继承主挑染色、5 区继承副挑染色，其余区跟随主色。

## 数据与兼容

表面分区使用 version 1、128×128 逻辑 UV 坐标。`bones` 以骨骼名索引，每项记录 `cube_count` 和 `faces`；每个面包含方块索引 `cube`、方向 `face`、原面范围 `uv_bounds`，以及带 `channel` 和 `uv` 顶点的 `parts`。分区随模型的骨骼、方块变换和左右镜像一起运动。

读取时校验编号、坐标、覆盖面积，以及当前模型的方块数量和各面 UV。资源包中无法匹配的骨骼使用像素遮罩。原模型只渲染一次，分色边界保持在原表面上。

兼容像素遮罩使用 version 3、256×256 像素坐标，尺寸字段为 `texture_width` / `texture_height`。每个 region 包含 `part`、`channel`、`runs`。`part` 为 FRONT / BACK / TAIL；`channel` 为 1–6；每条 run 为 `[y,x0,x1]`，终点 x1 不包含。遮罩外为主色。

`stripe01.json` 的 `preset` 为 `stripe01`，其他文件依次为 `style02` … `style08`。读取时校验身份与已注册部件：07 后发、08 尾巴定义无效；缺少合法部件时，该部件回退普通发色。

配置中的 `maneDyePreset` 保持 `stripe01`，表示分区模式；实际资源由 `ManeDye.maskName(config, part)` 根据部件款式选择。

每份像素遮罩限制 18 区、8192 条 run、1024×1024 尺寸和 256 KiB 大小；拒绝非法坐标、重复区域和同部件内重叠。01 仍支持旧 version 1 / 2 资源，旧通道 1 / 2 分别规范化为新色区 4 / 5；新增款式要求 version 3，避免误套旧通道含义。旧版客户端不能读取 version 3，联机双方应使用同版本。

`frontManeDyeColors`、`backManeDyeColors`、`tailDyeColors` 为长度 6 的数组，null 表示跟随主色。仅在缺少数组时，从旧 `maneDyeColor` / `maneDyeAccentColor` 迁移；之后以数组为准。非法颜色改为 null，数组长度规范为 6 项。

保存、复制和联机沿用整对象 JSON，现有预设的六个颜色继续使用。表面分区图集按实际色阶和调色模式共享；兼容像素遮罩另按部件及遮罩身份区分缓存。相同颜色合并图集格，关闭分色时使用普通发色纹理。资源重载、断线或退出时清理缓存；动态纹理上限为 128 项 / 64 MiB。

01、07 前发的旧挑染凸条已从源工程和运行时模型移除，分色使用本体表面的遮罩。渲染器仍跳过旧资源中的 `Style01FrontManeHighlight`，兼容保留该骨骼的资源包。
